Install

fennecdb is two programs, fennec-server and the shell, fennec, and a package for each language that reaches the server. Pick the way that suits your machine.

The download page picks the command for your machine and shows what the install script does.

The commands here install release {{version}}, so what they print is what that release prints. The rest of these docs describe the repository's main, which can be ahead of the release: a flag or a statement they show that your install lacks is in the next one, and fennec-server --help lists what yours has.

On Windows, the PowerShell script installs the two programs, or the image runs the server. The clients run anywhere their language does.

The install script

curl -fsSL https://fennecdb.com/install.sh | sh

It puts fennec-server and fennec in ~/.fennecdb/bin (FENNEC_INSTALL names another directory) with no sudo, and edits no shell file: it prints the line that puts the directory on your PATH and leaves that to you.

export PATH="$HOME/.fennecdb/bin:$PATH"   # in ~/.zshrc, ~/.bashrc or ~/.profile to keep it
  • It downloads the latest release from GitHub over https, with curl or a wget that checks certificates; FENNEC_VERSION={{version}} names a release.
  • It checks the tarball against the release's SHA256SUMS before it unpacks anything. That sum comes from the same release as the file, so it catches a damaged or cut-short download, not a release someone replaced.
  • Nothing runs until its last line. The script is functions, and main "$@" on its last line is what starts them, so a download cut short runs nothing. To read it before it runs: curl -fsSL https://fennecdb.com/install.sh | less (install.sh).
  • To remove it, delete ~/.fennecdb.
  • With --app, on a Mac with Apple silicon or on Linux, it installs the studio app instead.

Windows

In PowerShell, Windows PowerShell 5.1 or PowerShell 7:

irm https://fennecdb.com/install.ps1 | iex

Releases after 0.1.12 carry a Windows build for x86_64 and one for arm64, fennec-vX.Y.Z-x86_64-pc-windows-msvc.zip and fennec-vX.Y.Z-aarch64-pc-windows-msvc.zip: a folder holding fennec-server.exe and fennec.exe. The script takes the machine's, and no other: a release that does not list the zip for your processor is refused, named, and nothing is installed — an x86_64 build is not taken for an arm64 machine, which a Windows 10 for arm64 cannot run. Before the first of them, the script says the latest release has no build for Windows and installs nothing. The programs need nothing installed beside them, the C runtime built in: unzipped anywhere, they run from there.

  • It installs into your profile: %LOCALAPPDATA%\fennecdb\bin ($env:FENNEC_INSTALL names another folder), with no administrator. It touches no profile and no PATH: it prints the line that puts the folder on this session's PATH, and to keep it you add the folder to your user's Path — Start, Edit environment variables for your account — not the machine's.
  • It checks the zip against the release's SHA256SUMS before it unpacks anything, as the shell script checks a tarball. $env:FENNEC_VERSION = '0.1.13' before it names a release.
  • Nothing runs until its last line. The script is functions, and Install-Fennec @args on its last line is what starts them, so a download cut short runs nothing; PowerShell's own parser holds that, and that it invokes no expression, before the site serves it. Run through iex, it changes none of your session's settings or variables, but its functions — each named for fennec, Install-Fennec and Get-FennecArch among them — stay defined in your session until it ends. To read it first, open install.ps1 in a browser.
  • Not signed. The programs carry no Authenticode signature. What the script installs carries no mark of the web, which it takes off the zip once the sum holds, so nothing warns of it; a zip a browser downloads is marked, and SmartScreen warns of a program in it opened from Explorer ("Windows protected your PC": More info, Run anyway). Check its sum first (below), then Unblock-File the zip before you unpack it.
  • Without the network, copy the zip and SHA256SUMS from the release into a folder and run the script with $env:FENNEC_FROM naming it: it checks and installs from there.
  • To upgrade, run it again, a server running from the folder or not: a running program's file is renamed aside and removed once it stops, and if the second program cannot be replaced the first is put back, so the two stay the version they were. To remove it, delete %LOCALAPPDATA%\fennecdb.

On Windows the programs take a file's lock as everywhere else, so a second process over a served file is refused, and a checkpoint's or a compact's rename is made durable as on Linux and macOS, the file and its directory flushed. That rename replaces a file other programs hold open on NTFS and ReFS; FAT32 and exFAT have no such rename, so a checkpoint there fails and writes stop, which the server says as it starts. Keep a database out of a folder OneDrive, Dropbox or a backup agent reads: one holding the file can refuse the rename, which is tried again for a second before writes stop. On NTFS and ReFS the file is mapped, as on Linux and macOS, in views Windows 10 1803 and later lay end to end (an earlier Windows maps it anew as it grows); on FAT32, exFAT or a network share it is read into memory, as --no-mmap reads it, which the server says as it starts. The server stops on Ctrl+C, Ctrl+Break and a console's close, and runs as a service under a wrapper (Durability). A file server, a shell and an app's library are what Windows is for here: a node of tenants runs there, and a cluster and its router are Linux's.

Homebrew

brew install fennec-db/tap/fennecdb

The formula installs fennec-server and fennec, the shell, on macOS and Linux (arm64 and x86_64): the release's own binaries, checked against their SHA-256, not built on your machine. brew upgrade fennecdb takes the next release and brew uninstall fennecdb removes it.

.deb and .rpm

Each release carries a package for amd64 and one for arm64, with its checksum in SHA256SUMS; releases from 0.1.12 on have them.

curl -fLO https://github.com/fennec-db/fennecdb/releases/download/v{{version}}/fennecdb_{{version}}-1_amd64.deb   # arm64 on an ARM machine
sudo apt install ./fennecdb_{{version}}-1_amd64.deb
curl -fLO https://github.com/fennec-db/fennecdb/releases/download/v{{version}}/fennecdb-{{version}}-1.x86_64.rpm   # aarch64 on an ARM machine
sudo dnf install ./fennecdb-{{version}}-1.x86_64.rpm

They install fennec and fennec-server in /usr/bin and depend on nothing: the binaries are static.

A release tarball

TARGET=aarch64-apple-darwin   # or x86_64-apple-darwin, aarch64-unknown-linux-musl, x86_64-unknown-linux-musl
curl -LO https://github.com/fennec-db/fennecdb/releases/download/v{{version}}/fennec-v{{version}}-$TARGET.tar.gz
tar -xzf fennec-v{{version}}-$TARGET.tar.gz
cd fennec-v{{version}}-$TARGET
./fennec-server --help

The folder holds fennec-server and fennec, and nothing needs installing: run them from there, or copy them where your PATH looks. The release page lists every file.

The Docker image

The image holds fennec-server and nothing else: no shell, no libc, 7 MB. Its data lives in /data, which the command below keeps in a volume.

docker run -d --name fennecdb -v fennecdata:/data \
  -p 127.0.0.1:8080:8080 -e FENNEC_HTTP_TOKEN=a-token \
  ghcr.io/fennec-db/fennec-server:{{version}}

A container listens beyond localhost, so the server asks for a token, or for --insecure where you publish the port to your own machine only, as the Quickstart does. Its command is --http 0.0.0.0:8080 --file /data/data.fennec --sync 250: write every flag out when you override it, or the file is dropped. Run it in a container has the rest: one instance a file, memory limits, Kubernetes.

From source

For a build the releases do not have, or to work on fennecdb: clone the repository and build with cargo and make. Build from source has the commands, the tests and what each make target does.

The studio app

fennec studio is also an app (beta) that opens a .fennec file with nothing to start: it carries fennec-server and the shell. On a Mac with Apple silicon and on Linux the install script installs it instead of the two programs:

curl -fsSL https://fennecdb.com/install.sh | sh -s -- --app

On a Mac it downloads the release's fennec-studio-v{{version}}-macos-arm64.dmg, checks it against SHA256SUMS before it opens it, and copies the app into ~/Applications, no sudo. The app is unsigned (no Developer ID, not notarized). What curl downloads is not quarantined, so the app opens at once; the same DMG downloaded from the release by a browser is, and its first open asks once, in System Settings, Privacy & Security, Open Anyway. To remove it, delete ~/Applications/fennec studio.app.

On Linux, x64 or arm64, it first asks whether the system has what the app links: glibc 2.38 or later and WebKitGTK 4.1, which Ubuntu 24.04, Debian 13, Fedora 39 and later have and Ubuntu 22.04, Debian 12 and RHEL 9 do not. Where one is missing it says what to install and installs nothing:

sudo apt install libwebkit2gtk-4.1-0 libayatana-appindicator3-1   # Ubuntu, Debian
sudo dnf install webkit2gtk4.1 libayatana-appindicator-gtk3       # Fedora

Then it downloads fennec-studio-v{{version}}-linux-x64.tar.xz (or -arm64), checks it the same way, and puts the app in ~/.local/share/dev.fennecdb.studio/stable/app and its entry in your applications menu in ~/.local/share/applications/fennecstudio.desktop, no sudo. To remove it, delete those two, and the two files of the .fennec registration the app wrote in ~/.local/share (the studio's page names them); the folder above the app keeps its saved state.

On Windows, PowerShell installs it, Windows PowerShell 5.1 or PowerShell 7. irm | iex hands a script no argument, so here the script is made a script block and called with -App:

& ([scriptblock]::Create((irm https://fennecdb.com/install.ps1))) -App

It downloads fennec-studio-v{{version}}-windows-x64.zip (or -arm64, the machine's processor's, as for the programs), checks it against SHA256SUMS before it unpacks it, and puts the app in %LOCALAPPDATA%\dev.fennecdb.studio\stable\app and a shortcut, fennec studio, in the Start menu: no administrator, no PATH, and nothing it downloaded is run. The app is not signed. What the script downloads carries no mark of the web, so SmartScreen does not ask; the same zip a browser saved does, and the app's first start asks once (More info, Run anyway), and Smart App Control, where it is on, refuses it. To remove it, delete that folder and the shortcut, and the .fennec registration the app wrote under HKEY_CURRENT_USER (the studio's page has its three reg delete lines).

On either, a running app is not replaced: quit it, then run the line again. The zip and the tarball hold one folder, fennec-studio, which also runs where it is unpacked (bin\launcher.exe, bin/launcher).

Checking a download

A release's files are listed with their checksums in SHA256SUMS:

curl -LO https://github.com/fennec-db/fennecdb/releases/download/v{{version}}/SHA256SUMS
shasum -a 256 -c --ignore-missing SHA256SUMS    # Linux: sha256sum -c --ignore-missing SHA256SUMS

On Windows, the zip's sum beside its line in SHA256SUMS:

$zip = 'fennec-vX.Y.Z-x86_64-pc-windows-msvc.zip'   # or aarch64-pc-windows-msvc
(Get-FileHash $zip -Algorithm SHA256).Hash.ToLower()
Select-String -SimpleMatch $zip SHA256SUMS
