Compatibility and upgrades

From 1.0 a release only adds to what is listed here. A change that would break one of them waits for 2.0.

What 1.x promises

A 1.x release grows a surface: a new record kind in the file, a new route or optional field, a flag, a statement. It never changes or removes what was there. A feature is deprecated in a minor, kept for the rest of 1.x and removed only in 2.0. 0.x releases promise nothing.

What is not frozen

  • The Rust crates' API. None is published; use fennecdb through the server, the shell, the C library or the browser module.
  • The browser module's exports, which belong to @fennecdb/web and ship with its glue.
  • How a page lays out its IndexedDB or OPFS data. Only that the data restores.
  • The studio's pages and the desktop app (beta).

Upgrading

Upgrade replicas before primaries, and roll forward. For a cluster the order is archivers, routers, nodes holding replicas or standbys, then primaries (Sharding reference).

  • A newer replica follows an older primary. This order is not yet checked in CI; a script drives it by hand for record kind 13.
  • An older replica that meets a record kind or type tag it does not know stops and names it, for example record kind 13 is not a write. It never reads it as something else.
  • Such a record appears when a feature is first used, not when it is installed: the first create statement, a field with a second index. The release notes name each, so upgrade every reader first.
  • An older binary refuses a file a newer one has written to. Going back is safe only before a feature's first use.

The grammar epoch

A named statement is stored as its text with the grammar epoch it was parsed under. An open parses it again and, where the result differs, marks it broken until it is defined again. The epoch is 4, as it was in v0.2.0, and it stays 4 through 1.x. Raising it is a major version, and its notes name the stored statements it breaks.

Support

The latest 1.x minor gets every fix. The previous minor gets security fixes for six months after the next one is released. Release candidates are tagged 1.0.0-rc.N.
