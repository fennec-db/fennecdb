No shell and no libc in the image. Its data lives in /data, kept here in a volume. A container listens beyond localhost, so the server asks for a token of 32 bytes or more. Run it in a container has the rest.

fennec studio, the app

A window on the studio a fennec-server serves. The app starts the server it carries, one for each file, and shows that server's own /_studio/, so the window does what the studio does in a browser. Nothing of a database is written by the app itself.

  • A fileFile, Open… or a double-click in Finder. The window is on that file's own server; closing it stops the server once it has written its checkpoint.
  • A new databaseA name and a folder, a first collection if you like, and when a write is safe on disk. The bundled server makes the file.
  • Serve it to your appsA port, this Mac alone or your network, MCP and metrics. The token is kept in the Keychain, never on a command line.
  • ServersEach one served, running or stopped: its statements a second, median answer and connections, how to connect, and its output.
  • BackupsBack up now while it runs, sealed with a key file if you choose; Verify reads the folder as a restore would; Restore… never writes over a file.
  • A saved serverAn address and a token, kept in the Keychain and sent only to that address. The window is on its studio: no CORS to set up.

Security · The studio, in full

What the one command does

It asks GitHub for the latest release over https, checks your machine's tarball before it unpacks anything, and puts the two programs where you can see them. What you watch here is what install.sh prints.

  • No sudoYour home directory, and no shell file edited: it prints the PATH line and leaves that to you.
  • Checked before it is unpackedAgainst the release's SHA256SUMS. That sum comes from the same release as the file, so it catches a damaged or cut-short download, not a release someone replaced.
  • Nothing runs till its last lineThe script is functions, started by main "$@" at its end, so a download cut short runs nothing.
  • Gone in one lineTo remove it, delete ~/.fennecdb. To pin a release, FENNEC_VERSION={{version}}.

Check it, or build it

Check a download

curl -LO https://github.com/fennec-db/fennecdb/releases/download/v{{version}}/SHA256SUMS
shasum -a 256 -c --ignore-missing SHA256SUMS
# Linux: sha256sum -c --ignore-missing SHA256SUMS

A release lists every file with its checksum in SHA256SUMS; the release page lists the files.

The app

Its .dmg is in SHA256SUMS too, so the same two lines check it, and the one-line install checks it before it copies anything. It is signed ad hoc, not by Apple: macOS asks once before it first opens, and xattr -cr "/Applications/fennec studio.app" does what Open Anyway does.

From source

For a build the releases do not have, clone the repository and build with cargo and make: Build from source.

make studio-desktop
open "integrations/studio-desktop/build/stable-macos-arm64/fennec studio.app"

The app from a checkout, unsigned, with the server and the shell built from the same checkout. It needs Node, npm and Rust, and fetches its build tool into its own directory: nothing is installed globally. An app you build opens as it is (Desktop app).
